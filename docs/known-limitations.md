# Known limitations

This page describes user-visible behavior and limits in the current source. Current work and acceptance criteria belong to the public issue tracker.

## Data and values

- **SQL editor input is bounded** ([#1299](https://github.com/cozyGarage/BookiE/issues/1299)). Opening or dropping a SQL file, pasting text and restoring saved drafts enforce a 256 KiB UTF-8 physical-line limit and an 8 MiB editor limit. Inputs are refused before changing the editor. An older saved draft over either limit remains saved and opens as a read-only notice until valid SQL replaces it. These limits do not cap total process memory.
- **Full-table export is available for PostgreSQL only** ([ADR 0014](decisions/0014-full-table-export-snapshot.md)). It reads one repeatable-read snapshot and holds a read transaction open until the export ends. Every other engine refuses it; export the current page or a loaded query result instead. Database snapshots for backup and restore are a separate feature with an accepted design that is not available in the current application ([ADR 0015](decisions/0015-database-snapshots.md)).
- **Export writes one table or result at a time, except Export Tables as CSV.** The optional maximum-row setting caps the selected scope and reports omitted rows. It does not fetch unloaded values or bypass snapshot requirements. Export Tables as CSV takes up to 256 tables, needs a driver with snapshot export, and writes CSV only ([#3089](https://github.com/cozyGarage/BookiE/issues/3089)). The data dictionary export stops at 100,000 metadata rows and refuses an incomplete catalog instead of writing a partial file ([#3097](https://github.com/cozyGarage/BookiE/issues/3097)).
- **Large results have materialization limits** ([#1272](https://github.com/cozyGarage/BookiE/issues/1272)). Materialized results stop at 1 million rows, 10 million cells, or 64 MiB estimated size. Single-statement PostgreSQL `SELECT`s stream cursor pages through `PolicyGuard`. Each result cache targets a 64 MiB estimated row window, while the GTK app shares a 256 MiB estimated page budget across streamed-result pages, loaded pages, pins and exports. Page decode and reload reserve budget before work, so in-flight reservations count. These are row-payload estimates, not an RSS ceiling; GTK allocations, driver buffers and non-streaming materialized results are outside the shared budget. A process-local encrypted spool ([ADR 0025](decisions/0025-transient-result-page-spool.md)) has a shared 1 GiB quota and a 4,096-page cap per result. After the stream ends, spooled pages are released from the resident cache and loaded on demand; a page that could not be spooled remains in memory. Other statement shapes and engines remain materialized. Find in all rows, Show matching rows and Compare read the saved pages ([ADR 0029](decisions/0029-whole-result-operations-on-the-spool.md), [ADR 0030](decisions/0030-audit-local-result-comparison.md)); Show matching rows writes a second spool against the same quota, and `BOOKIE_SPOOL_DIR` can place spool files on disk when the temporary directory is memory-backed. Sorting the whole result is not available. Compare cannot yet compare results that have two columns with the same name, such as a join returning two `id` columns, and Show All Rows Not Equal to This Value keeps NULL rows by design ([ADR 0029](decisions/0029-whole-result-operations-on-the-spool.md)). These budgets bound retained data, not total process memory.
- **SQL result filters apply only to loaded rows.** Filter and sort actions are local and do not re-run SQL. Clearing a filter restores loaded rows. Settings carry across reruns of the same statement and pin/unpin while the result remains current or pinned. Selection follows source-row identity when a materialized result is rerendered; a fresh query resets selection. Settings do not survive an app restart.
- **File exports use text markers for undecodable cells** ([#883](https://github.com/cozyGarage/BookiE/issues/883)). CSV, JSON, Markdown, HTML, XML, Excel, copied text and MCP CSV content use a visible `<undecodable TYPE>` string; these text representations do not retain a separate typed marker, so a real text value with the same spelling is ambiguous. SQL export refuses the value. MCP JSON retains an explicit tagged `undecodable` value.
- **Grid cells show bounded text.** Text and JSON cells display at most 512 Unicode characters. Text shows the remaining byte count; JSON shows an ellipsis when bounded serialization stops before the end. Values over 8 KiB use a typed preview. **View Value** displays at most 64 KiB of rendered text or the first 16 KiB of binary data as hex. It includes pending edits and drafts. Persisted rows are refetched by primary key; keyless rows use the loaded value. **Copy Value** copies complete text and JSON values, and copies binary values as a full `\x` hex form of every byte. Text and JSON can be edited in the full-value dialog up to 1 MiB. Invalid JSON cannot be staged, and SQL NULL, empty text, JSON `null` and text `null` remain distinct.
- **Binary UUID display uses type and length metadata.** `BINARY(16)` and `VARBINARY(16)` cells, and SQL result columns reported as `BINARY` or `VARBINARY` that contain exactly 16 bytes, paint as UUID text. SQL result metadata does not report the declared width, so a 16-byte binary value that is not semantically a UUID may also appear in UUID form. UUID byte-order conventions such as `UUID_TO_BIN(value, 1)` are not detected. The underlying bytes remain unchanged for edit and write paths; **Copy Value** and binary-preserving exports retain the full byte value.
- **Hidden-column projection does not fetch hidden non-key values.** Full-row copy, row JSON and current-page export refuse when required values were not loaded ([#596](https://github.com/cozyGarage/BookiE/issues/596)).
- **A table without a primary key cannot be deleted from the grid.** There is no all-column fallback, by design.
- **Browse page order can change without a unique ordering.** Rows may be skipped or repeated between pages, even when the database is unchanged. Concurrent inserts, updates and deletes can also shift offset pages. PostgreSQL ordinary tables use `ctid` as a tie-breaker when no primary key is available; it is not a durable row identity. Other engines do not currently guarantee a tie-breaker for keyless tables.
- **ClickHouse nested values** can be exported as JSON. SQL literal export and parameter binding refuse nested values when required type metadata is unavailable.
- **ClickHouse ambiguous local times:** a `DateTime64` in a repeated or missing daylight-saving hour is shown as undecodable and is not converted to a literal.
- **MySQL generated columns:** Structure edits do not preserve every generation expression. Expressions rejected by the metadata safety filter can retain earlier failure or loss behavior ([#1248](https://github.com/cozyGarage/BookiE/issues/1248)).
- **SQLite real numbers:** negative zero and NaN cannot be bound as parameters.
- **SQLite JSON aggregates can vary by system library version** ([#1545](https://github.com/cozyGarage/BookiE/issues/1545)). On older SQLite libraries, a JSON object aggregate with a SQL NULL key may produce malformed JSON. The driver uses the system SQLite library and returns its result.
- **SQL row export does not preserve every server-assigned value.** When column metadata marks a value as generated, SQL export and Copy as INSERT omit it. Auto-increment columns are also omitted for PostgreSQL and SQL Server, so replay assigns fresh values. Row statements do not restore sequence state or remap foreign keys. Do not use them as a relational backup. For PostgreSQL, use the [dedicated backup tools](user-guide.md#back-up-and-restore-postgresql).
- **SQL Server server-owned columns are omitted from row writes.** CSV import drops mapped IDENTITY, computed and rowversion fields; Copy as SQL and SQL export omit generated values so the destination creates them. PostgreSQL, MySQL/MariaDB and SQLite can import explicit auto-increment values when mapped.
- **Read-only ClickHouse accounts can browse without changing query settings** ([#1237](https://github.com/cozyGarage/BookiE/issues/1237)). The server may encode `NaN` and infinities as JSON `null` when the account cannot change output settings. Nulls in floating-point columns are therefore marked undecodable because the driver cannot distinguish those values from SQL `NULL`. Decimal trailing zeros may also be omitted; the numeric value is preserved, but its declared scale is not.
- **Unzoned PostgreSQL `timestamptz` CSV values** are interpreted as UTC ([#857](https://github.com/cozyGarage/BookiE/issues/857)). Include an explicit zone to avoid ambiguity.
- **MongoDB browse pages are separate observations, not one point-in-time view.** Grid updates compare original values of edited fields; deletes compare materialized non-key fields ([ADR 0024](decisions/0024-keyed-grid-writes-check-what-they-overwrite.md)). These checks do not cover fields absent from the loaded set. Column types come from a bounded `_id`-ordered sample of at most 128 documents combined with the displayed page; other fields or types may remain undiscovered. The sample refuses metadata with more than 4,096 distinct fields or 1 MiB of field-name bytes. Mixed-type columns are read-only. Reverse, last-page, explicitly sorted and keyless deep-page navigation use offset pagination.
- **MySQL failed batches do not undo every side effect.** InnoDB changes are rolled back, but writes to nontransactional tables and some trigger effects can persist. The connection that ran a failed batch is closed, so its session effects (named locks, user variables) do not reach later queries.

- **View Value** decodes MessagePack and schema-less Protobuf only, for binary values up to 64 KiB. Avro and igbinary values show the hex dump only: Avro needs a schema that BookiE does not fetch, and igbinary has no decoder.

## Editing and connections

- **View editing is enabled in the app for PostgreSQL, MySQL/MariaDB and SQL Server.** Automatically updatable single-table views must expose the complete primary key and have no INSTEAD OF trigger or rule. MySQL/MariaDB base-table/key discovery was repaired in [#3392](https://github.com/cozyGarage/BookiE/pull/3392). The app path was checked by hand on MySQL 8.4, MariaDB 11.8 and SQL Server 2022 (staged edit, SQL preview, Save, base-table read-back); an aggregate view on MariaDB stayed read-only with its explanation. SQL Server's metadata implementation refuses aggregates, grouped and unsupported query shapes and disables view inserts.
- **Session temporary tables are listed for PostgreSQL, SQLite and MariaDB when the server exposes their metadata.** The sidebar lists only the active editor session's tables and opens their rows in that session. MySQL, SQL Server and DuckDB temporary tables are not listed: the tested MySQL server does not expose its temporary tables through the driver metadata query; SQL Server appends system-generated suffixes to local temporary-table names in `tempdb`, and BookiE does not yet have a session-safe listing; DuckDB does not provide a dedicated BookiE editor session. Session-aware Structure editing is also unavailable ([#3098](https://github.com/cozyGarage/BookiE/issues/3098)).
- **Grid saves compare only edited cell values, and relational deletes check the key only** ([ADR 0024](decisions/0024-keyed-grid-writes-check-what-they-overwrite.md)). Case-insensitive equality may miss a case-only text change ([#1820](https://github.com/cozyGarage/BookiE/issues/1820)). A value changed and changed back is also not detected. Engines without checked writes save by key and warn after commit when no row matched.
- **The GTK app applies edited connection settings only to the selected session** ([#3093](https://github.com/cozyGarage/BookiE/issues/3093)). Opening a saved connection whose host, port, database, user, password, socket, encryption, SSH tunnel, authentication method, read-only mode, environment or timeout changed offers to keep the open session or reconnect it. Reconnecting cancels and waits for that connection's running queries, prompts to save or discard its pending row and structure edits, and asks before rolling back an open transaction. Only that connection's tabs and session are closed and restored; other open connections stay active. Name, colour, tags and favourite apply without reconnecting. If activation fails after the previous session closes, its saved workspace remains available to open again.
- **Redis supports a single host/port endpoint.** Sentinel and Cluster topologies are unsupported.
- **PostgreSQL behind a connection pooler:** PgBouncer in session mode works. Transaction mode requires support for prepared statements (PgBouncer 1.21 or newer with `max_prepared_statements` above 0); otherwise backend switching can cause prepared-statement conflicts. Session features such as `SET`, temporary tables and transactions spanning statements require session pooling.
- **Jump hosts need the built-in SSH client.** The system OpenSSH client refuses saved jump hosts, so the form disables the jump host list while "Use system OpenSSH" is on. A key passphrase saved for a jump host cannot be cleared in the form; remove the jump host and add it again.
- **Missing SQLite attachment files are skipped on connect.** Configured files that exist but fail to attach cause the connection to fail.
- **Local socket endpoint differences:** PostgreSQL selects a socket directory plus port; MySQL and MariaDB select the full socket-file path. Local sockets reject TLS and SSH and never fall back to TCP. Connection URLs use `?socket=/path/to/mysqld.sock` for MySQL/MariaDB or `?host=/socket/directory` for PostgreSQL, with an empty host or `localhost` and no other option.
- **SQL Server cancellation covers queries and statements, not catalog reads or transaction batches.** Stop sends a TDS Attention and keeps the connection. A multi-statement batch keeps the statements that finished before Attention; catalog reads and transaction batches still retire the connection when interrupted.
- **The SQL Server driver does not refuse writes on a read-only connection by itself.** SQL Server has no per-connection read-only mode, so the driver sends a write it is given; only the policy guard (every GUI, agent and MCP path goes through it) refuses it. The shared driver conformance suite records this as the one case SQL Server skips.
- **DuckDB read-only flat files** require Linux and a writable directory on the same filesystem as the input file. The driver pins the selected file through a private link. Read-only in-memory connections are refused.

## Interface

- Multi-cursor editing is unavailable in the GTK editor: GtkSourceView has one caret and no multi-cursor API ([#2210](https://github.com/cozyGarage/BookiE/issues/2210)). The GPUI editor has it ([GPUI README](../apps/gpui/README.md)). Split panes and SQL code folding are available. Vim keys are an opt-in preference. Preview tabs are temporary and are not restored after restart; kept tabs are restored. Query history opens in a docked panel.
- The PostgreSQL catalog lists materialized views, routines, triggers, sequences, extensions and roles. The activity dialog is a plain result grid; it does not provide a typed activity console.
- **Supplemental sidebar catalogs have a 64 MiB estimated retained-data budget per window.** The estimate counts vector capacity and catalog-object string capacities. A refreshed catalog that exceeds the remaining budget is discarded and the previous cached entries of that kind are removed. This estimate excludes transient driver results and GTK tree-model allocations; it is not a process-memory limit.
- Server messages appear in a Messages section under the result of a statement: PostgreSQL notices and warnings (`RAISE`), SQL Server `PRINT` and `RAISERROR` at severity 10 or below, and MySQL or MariaDB warnings read with `SHOW WARNINGS` after a statement that reported any ([#550](https://github.com/cozyGarage/BookiE/issues/550)). A statement keeps at most 100 messages and 64 KiB of text, each message at most 4 KiB, and the section says how many more were not shown. Other engines report none. Streamed PostgreSQL results, transactions held by the changeset Save flow, and statements run through `execute` show no messages. A MySQL or MariaDB script of several statements shows the warnings of its last statement only. Agents and MCP clients never receive messages, because a message can echo row data, and the audit journal stores no message text. The status line shows client run time without approval wait, and its tooltip lists the approval wait. The server does not report its own execution time to BookiE. The tooltip shows time to first row for streamed results, completion time for results with no rows, and transfer time after the first row. Buffered results that contain rows omit the first-row and transfer values.
- The PostgreSQL table and index health report is read-only and PostgreSQL only. It shows the top 50 rows per report from built-in statistics, so counts reset with the server statistics and bloat is a rough estimate from dead rows, not a measurement. Duplicate index detection compares plain column indexes and skips expression indexes. Other engines have no health report. It needs no extension, so it does not use `pgstattuple`.
- Foreign-key value pickers offer at most 100 candidates for single-column foreign keys; composite foreign keys are skipped. PostgreSQL, MySQL/MariaDB and SQL Server unfiltered browse counts use engine estimates when available and show an estimate marker. Filtered tables and unavailable estimates fall back to exact counts, which may scan the table. Go to Referenced Row, scalar enum/set pickers and tab-separated row paste are available.
- PostgreSQL schema hiding is a per-connection GUI visibility preference ([#580](https://github.com/cozyGarage/BookiE/issues/580)). Large exclusion lists use a server-side anti-join, covered by a PostgreSQL 18 driver regression with 9,900 hidden schemas and 14,000 relations ([#2602](https://github.com/cozyGarage/BookiE/issues/2602)). This is query-path coverage, not end-to-end latency or memory evidence; the many-schema release profile and GTK-stall bound remain open. The standalone MCP bridge does not receive the GUI's hidden-schema set; database-role privileges still govern the objects it can list.
- Database snapshots and one-click rollback are unavailable ([ADR 0015](decisions/0015-database-snapshots.md)). PostgreSQL logical backup and restore use the installed `pg_dump` and `pg_restore` tools; see the [user guide](user-guide.md#back-up-and-restore-postgresql). They are not point-in-time snapshots.

## Platforms and packaging

- Native builds require GTK 4.24, libadwaita 1.10 and GtkSourceView 5.22 or newer ([ADR 0021](decisions/0021-toolkit-floor.md)). Older toolkit stacks are unsupported for native packages.
- The shipped product is the Linux GTK 4 and libadwaita client. Windows and macOS have no shipped package. [ADR 0052](decisions/0052-gpui-is-the-cross-platform-frontend.md) chooses GPUI as the cross-platform frontend and keeps GTK in parallel; GPUI is not packaged or released until that ADR's conditions hold. See [platforms](platforms.md) for Arch and AppImage install paths.

## Operation outcomes

- **PostgreSQL transaction outcome can remain unknown after session loss.** A disconnected session cannot confirm whether its transaction committed. BookiE records an unknown outcome and blocks governed writes for that connection. A fresh session can run reads and end its read-only snapshot with ROLLBACK. Commits and other governed writes stay blocked until the outcome is reconciled. The app has no in-app reconciliation action ([#947](https://github.com/cozyGarage/BookiE/issues/947)).

## GPUI frontend (`apps/gpui`, not shipped)

Limits of the GPUI frontend after the DataTable change. It is the chosen cross-platform frontend ([ADR 0052](decisions/0052-gpui-is-the-cross-platform-frontend.md)) and is not included in packages or releases yet.

- **Cell selection:** a cell is always selected while rows are shown (the top-left cell at first), so the cursor is always visible.
- **Sidebar:** the narrow header label clips when the pane is narrow; connection import and export menu entries report that they are not available yet.
- **CSV delimiter:** the GPUI frontend has no CSV import and no export dialog; Export and Copy as CSV write to the clipboard. The palette command `csv delimiter <text>` (1 to 8 characters, no quote or line break) sets a multi-character delimiter for those copies until the app closes, and "CSV delimiter: back to the comma" resets it ([#3096](https://github.com/cozyGarage/BookiE/issues/3096)).
- **GPUI export row limit:** the palette command `export limit <n>` (a whole number of at least 1) caps Export as CSV to the first n rows of the selection or page until the app closes, and the status line says when more rows were not exported; "Export limit: remove" clears it. It limits clipboard exports only and never fetches rows that are not loaded ([#3089](https://github.com/cozyGarage/BookiE/issues/3089)).
- **Settings:** an Appearance page with a Dark theme switch and font family and size fields; the palette opens the page.
