## Findings

### R1: P1, empty grid edits bypass NULL and required-field validation

Location: [driver parser dispatch](../crates/app/src/ui/browse_tab/value_parse.rs),
`parse_input_for_driver` at line 49 and MongoDB decimal handling at line 161.

The shared `parse_input_for_column` handles empty input before parsing: nullable
or defaulted columns become `Value::Null`; required columns refuse. The driver
dispatcher calls its specialized parsers first. The new MongoDB Int32 path and
other MySQL integer, PostgreSQL numeric and DuckDB temporal paths therefore
bypass the shared rule. The probe checked seven driver/type combinations: six
rejected the empty edit, while MongoDB decimal accepted the empty input
as `{"$numberDecimal":"0"}`. That marker reaches `value_to_bson` as Decimal128.
Clearing the cell can stage a zero write. Required-field validation is bypassed
on this path too.

The existing width/precision tests use nonempty inputs. They miss the interaction
between the new dispatch and an established grid behavior.

Required regression: run empty nullable, defaulted and required inputs through
the driver dispatcher for every specialized branch. Include a native MongoDB
keyed save that proves a cleared nullable decimal becomes BSON Null, and a
required-field refusal that preserves the original document. Put the shared
empty-input rule before specialized parsing; preserve current nonempty behavior.

Resolution (2026-10-02): `parse_input_for_driver` now delegates exact empty
input to the shared parser before driver-specific dispatch. A matrix regression
covers nullable, defaulted and required metadata for MySQL integer, MongoDB
decimal, PostgreSQL numeric and DuckDB timestamp types. The MongoDB 7 app/server
contract now clears the Decimal128 cell through the keyed-update path and
asserts the stored value is BSON Null. Both focused unit and Docker contract
tests passed. The native fixture is nullable, so required-field behavior is
proved at the dispatcher boundary rather than with a MongoDB server schema.
The strict value layer also passed all 181 selected contracts across 11 suites
with Docker access; its report is under `target/quality/20261001T220436669945Z-layers/`.

### R2: P1, the real grid edit path changes text before the tested parser

Location: [row edit handler](../crates/app/src/ui/browse_tab/row_ops.rs), lines
277–286, and `normalize_single_line_input` in the app parser.

Every non-JSON edit goes through `split_whitespace().join(" ")`. A text input
`"  padded  CHAR  "` becomes `"padded CHAR"`. This removes leading/trailing spaces
and repeated interior spaces even when the input has no newline. PostgreSQL
text arrays are classified as text, so spaces inside quoted array elements can
also change before binding.

The helper predates this continuation. The new MySQL padded CHAR and PostgreSQL
array contracts call parsers/builders directly and do not prove the behavior of
the actual grid handler. The padded CHAR CSV test remains valid for CSV.

Required regression: exercise edit preprocessing plus parser plus keyed save for
VARCHAR/CHAR and a text array containing a repeated-space element. Assert native
bytes and sibling row identity. Preserve text exactly, or refuse input that the
editor cannot transport exactly. Do not silently normalize a supported value.

Resolution (2026-10-02): `normalize_single_line_input` now replaces only CR/LF;
other whitespace remains byte-for-byte unchanged. Unit coverage checks padded
text and a quoted PostgreSQL array through the parser and keyed-update builder.
The PostgreSQL 16 server contract also performs a native keyed array update and
checks exact array text plus sibling row identity. The focused unit and server
tests passed. Clipboard newlines are still mapped to spaces by design.

### R3: P2, PostgreSQL wide numeric CSV plans bind text without a numeric cast

Location: [CSV statement construction](../crates/core/src/import/plan.rs), line
115, and [INSERT construction](../crates/core/src/sql_dialect.rs), line 264.

The new wide-decimal fallback accepts a 40-digit value for `numeric(65,0)` as
`Value::Text`. The planner generates `INSERT ... VALUES ($1)`. The driver binds
that value as PostgreSQL text. A real PostgreSQL execution fails with SQLSTATE
`42804`: the destination is numeric but the expression is text.

The keyed UPDATE builder already has `postgres_numeric_cast_type`; INSERT only
consults the array and temporal allowlists. Adding a cast to INSERT alone would
still miss CSV's synthetic statement shape, which currently uses `Value::Int(0)`
for a numeric column. Mixed narrow/wide rows also need one consistent parameter
representation. This is the same class of consumer bug fixed for temporal CSV.

Required regression: default CSV export/import of a declared wide numeric, mixed
narrow/wide values and NULL, comparing native `numeric::text` after actual plan
execution. Cover draft INSERT and keyed UPDATE siblings. Reuse the existing safe
numeric allowlist; do not interpolate catalog metadata into SQL. Unconstrained
NUMERIC and special tokens need a separate explicit support/refusal decision.

Resolution (2026-10-02): the existing PostgreSQL numeric cast allowlist now
drives both draft INSERT SQL and the import plan's synthetic statement shape.
Wide numeric rows use `::text::pg_catalog.numeric`; one plan carries narrow,
wide and NULL values with a stable parameter type. Unit tests cover the builder
and plan. A PostgreSQL 16 contract exports a typed source table to default CSV,
imports it through the plan and compares exact `numeric::text` results for all
three rows. Focused tests passed. Unconstrained NUMERIC and special-token policy
remain separate scope.

### R4: P2, temporal CSV conversion reintroduces the PostgreSQL year-zero bug

Location: [CSV temporal parameter conversion](../crates/core/src/import/plan.rs),
lines 161–164.

A real PostgreSQL `DATE '0001-01-02 BC'` decodes to chrono year zero. Default CSV
export writes `0000-01-02`; CSV parsing accepts it. The new text-cast plan sends
that text to `pg_catalog.date`, and PostgreSQL rejects it with SQLSTATE `22008`.
The probe verifies the destination remains empty after refusal.

Existing era contracts prove typed binding and SQL export, where the
`postgres_temporal_text` helper already formats BC years correctly. Temporal CSV
tests cover ordinary finite values, infinities, end-of-day time and timetz, so
they miss this sibling path. The conversion also uses direct chrono formatting
for timestamp and timestamptz.

Required regression: DATE, TIMESTAMP and TIMESTAMPTZ BC values through default
CSV and actual INSERT plans, comparing independent native wire/text oracles.
Include years 1, 9999 and 10000, and mixed finite/infinite/NULL rows. Reuse
`postgres_temporal_text` when converting typed values to PostgreSQL text.

Resolution (2026-10-02): BC chrono values now use `postgres_temporal_text`;
extended positive years from RFC3339 CSV have their leading `+` removed and
`T` separator normalized into PostgreSQL text. A focused core contract proves
year zero maps to 1 BC. A PostgreSQL 16 CSV contract covers DATE, TIMESTAMP and
TIMESTAMPTZ at the BC/AD boundary, years 9999 and 10000, and NULL, then compares
native wire bytes before and after. Both tests passed.

runs driver integration targets, MCP BSON and policy sessions. Neither selection

- `value_contract_mongodb_date_grid_edit_preserves_millisecond_instant`
- `value_contract_mongodb_decimal128_grid_edit_preserves_wide_precision`
- `value_contract_mongodb_nested_document_edit_preserves_extended_bson_and_row_identity`
- `value_contract_mysql_unsigned_integer_grid_edits_refuse_coercion_and_preserve_u64`
- `value_contract_mysql_spatial_grid_refusal_preserves_native_bytes`
- `value_contract_mysql_bit_parser_edits_preserve_native_values`
- `value_contract_mongodb_late_mixed_page_refreshes_grid_and_refuses_edit`

The strict local `values` run executes all seven, and they passed during this

Resolution (2026-10-02): the `app-server` registry now owns all eight previously

The ignored-test inventory fails if any app Docker contract lacks an isolated
registration, and the CI harness asserts the complete registry. The DuckDB CI
job now runs the app's `value_contract_duckdb` tests with its feature enabled.
All nine isolated app-server tests and all five feature-enabled DuckDB app
contracts passed locally. The generated ignored-test ledger was refreshed.

### R7: P1, XLSX numeric cells can silently lose finite float precision in Excel

Location: [XLSX cell writer](../crates/core/src/export/xlsx.rs), `write_cell`.

Every finite `f64` was emitted as an XLSX numeric cell. That includes negative
zero, subnormals, values with more than 15 significant decimal digits, and
magnitudes Excel does not support as worksheet numbers. The raw XML token can
round-trip through Rust while Excel rounds or rejects it, so the existing token
tests did not prove spreadsheet-consumer preservation.

Required regression: prove precision-risk floats are text cells and safe finite
values remain numeric. Cover Excel's documented numeric limits and 15-digit
precision rule. Keep exact text for values that would otherwise lose digits.

## Proposed sprint and agent handoff improvement

R1–R5 and R7 are resolved. Continue with B3-P1: reconcile the remaining
engine/type/consumer matrix, record which unsupported cases block 0.2.0, then
assign one bounded contract at a time. Keep the approved B3 → B4 → Arch Wayland
→ Debian/GNOME sequence. Existing native support blockers stay visible and are
not silently dropped to close B3.

The local build-cache task is in the sprint plan. The 2026-10-02 checkout
already reuses `linux/target`, which measures 82 GiB, including 45 GiB of
incremental artifacts. Benchmark cold/warm rebuilds and inspect profile/feature
duplication before choosing a disk-retention policy; keep cache cleanup out of
normal test commands unless it preserves useful artifacts.

Use one row per engine/type/consumer contract with these fields:

```text
ID | invariant | source revision | outcome | regression selector | execution gate
   | independent oracle | evidence | remaining gap | acceptance decision
```

Outcome remains exactly typed support, exact text fallback, explicit refusal or
untested. Track acceptance separately: a tested refusal can satisfy a safety task
while exact native support is still open. Freeze the finite set of 0.2.0 contracts
and explicitly decide which unsupported families block release. A phrase such as
"other nested combinations" needs named cases or a recorded scope decision;
otherwise agents can expand B3 indefinitely.

Reuse the [existing agent template](validation-playbook.md#agent-task-template).
For each task add the consumer path, known sibling callers, selected regression,
gate owner and stop condition. Example for the first fix:

```text
Task: B3-R1; baseline: b90cb4e38c1a98f41b552e03f739f9c51c67810f
Invariant: empty grid input obeys nullable/default/required rules for every driver.
Read: row_ops.rs -> parse_input_for_driver -> specialized parser -> keyed builder
      -> driver binding. Read sibling dispatch branches before editing.
Allowed edits: app value_parse.rs and existing parser/MongoDB test modules;
               runner registry/workflow tests only if needed for test ownership.
First proof: empty MongoDB decimal currently becomes a zero marker.
Acceptance: empty nullable -> NULL; required -> refusal and unchanged native row;
            valid nonempty width/precision cases keep their current behavior.
Run: focused parser tests, native MongoDB regression, registered app-server gate,
     strict values layer; applicable formatting/Clippy/size checks.
Return: failing-before/passing-after evidence, exact selectors, source hashes,
        gate ownership and all blocked/not-run scopes. Stop after this contract.
```

Update one current board row after a fix. Put before/after details in the evidence
ledger and link it from the board. Refresh the matrix only for the affected
contract. Run mutation checks after meaningful assertion changes; mutation
success cannot replace a missing end-to-end consumer contract.
